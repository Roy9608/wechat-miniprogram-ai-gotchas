# 微信小程序 AI 开发失败模式库

给 AI 看的，不是给人看的。

不是教程，不是 API 手册，不是最佳实践集。是一份**失败模式清单**：记录 AI 写微信小程序时，在哪些地方会写出"看起来完全正确、编译也通过、但就是不工作、而且不报错"的代码。

## 为什么需要这个东西

AI 写 Web 前端很强，因为训练数据里 Web 代码是海量的。它把同一套直觉搬到小程序里，大部分时候也对——直到某些地方突然失效。

失效的方式很有特点：

- 不抛异常
- 不打错误日志
- 编译器不警告
- 模拟器可能还正常
- 真机上就是不对

人类工程师踩过一次就记住了，AI 每次都会重新踩，因为它的"直觉"来自另一个平台。

官方文档帮不上忙：官方文档按**功能**组织（这个 API 怎么用），而这里的知识按**事故**组织（为什么这段代码不工作，但什么错都不报）。

## 收录标准

一个条目要进来，必须四条全中：

1. **静默或误导** —— 不报错，或者报的错指向错误的方向
2. **AI 的默认写法会中招** —— 从通用 Web / 原生 JS 经验推演出来的写法，正好是错的
3. **可复现** —— 说清楚在什么条件下必然出现
4. **有明确修法** —— 不是"注意一下"，是具体怎么写

四条缺一条就不收。**"这个 API 好用"这类内容一律不收**——那是教程，网上有。

## 怎么用

**方式一：人读，然后粘给 AI。** 你遇到某个诡异问题时，来这里搜症状关键词，把对上的那一条整篇贴进对话。比描述半天"我点按钮没反应"有效得多。

**方式二：让 AI 自己读。** 把 `gotchas/` 目录丢给 AI 让它读一遍再动手。适合在开始一个新页面、或者要改一批存量代码之前做。

**方式三：让 AI 自动读。** 仓库根目录的 [`AGENTS.md`](AGENTS.md) 就是干这个的——20 条禁令，各类支持该约定的 AI 编程工具（Cursor / Claude Code / Codex 等）在开工之前会自动读取它。复制到你自己的小程序项目根目录，删掉不适用的部分即可。

```

└── check-bindings.js     检查事件绑定有没有对应方法（零依赖，可直接跑）
gotchas/
├── README.md             条目索引
├── 01-silent-failure/    静默失败：不报错，就是不工作
├── 02-platform-rules/    平台限制：官方规则如此，写了也不生效
├── 03-toolchain/         工具链与编译器：代码没错，环境在坑你
└── 04-batch-edit/        批量改码陷阱：跟小程序无关，但 AI 高频翻车
```

每条一个文件，文件名用现象短语的英文短名（如 `setdata-then-scroll.md`），方便在对话里直接引用。

## 一条记录长什么样

必备五段：

1. **症状** —— 用户视角看到什么，控制台看到什么
2. **AI 的默认写法** —— 会踩雷的那段代码，以及 AI 为什么会这么写
3. **根因** —— 为什么这么写不工作
4. **正确写法** —— 可直接用的代码
5. **怎么验证没踩** —— 不靠"看起来对"，靠什么确认

**不是每一类坑都套得上这五段。** 工具链类的事故没有「错误代码」，用「AI 的错误反应 + 排查顺序」替代第 2、4 段；按需增补「反例」「元案例」也行。硬套模板比不套更糟。

第 2 段是这份库的核心。只写"正确写法"的文档满地都是，写清楚"错的为什么看起来对"的很少。

## 关于 tools/

目标是每条事故配一个检查脚本，但只收满足三条的：**零依赖、能独立跑、不含任何业务假设**。目前只有 1 个。

从真实项目里搬出来的脚本，只要带着硬编码路径、业务变量名白名单或具体数据结构，一律不收——改造后没法在真实项目上验证的代码，宁可不发。数量不值钱，能跑且不骗人才值钱。

## 不做什么

- 不收教程、入门指南、API 用法说明
- 不收"性能优化建议"这类没有明确对错的东西
- 不收业务代码、业务数据结构、具体项目的实现细节
- 不收任何具体项目、客户、品牌、产品名称
- 不做框架选型推荐（原生 / Taro / uni-app 各有各的坑，这里只记原生）

## 现状

早期，但骨架完整：`AGENTS.md` 20 条禁令、3 条完整样例、1 个验证过的检查脚本，另有 19 条现象已确认、条目待写（见 `gotchas/README.md`）。

这个库的价值不在于一次写多少条，而在于**每踩一个新坑就加一条**。攒到几十条才有分量。
