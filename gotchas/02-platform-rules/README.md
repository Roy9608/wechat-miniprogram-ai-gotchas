# 02 · 平台限制

官方规则就是这样，写了不生效，通常也不给提示。

这一类的特点和 01 的区别：

- **01 静默失败**：写法本身有问题（时序、缺失、状态不同步）
- **02 平台限制**：写法没错，是平台不提供这个能力。你在别的平台能这么干，在这里不能

## 待收录

| 状态 | 现象 |
|---|---|
| ☐ | WXML 不能渲染 HTML 字符串，标签会原样显示 |
| ☐ | 朋友圈打开的是「单页模式」，`switchTab` 等能力全部禁用 |
| ☐ | `wx:key="index"` 用在二维数组上会报警告 |
| ☐ | 低版本客户端没有某 API，直接调会崩，必须先判存在性 |
| ☐ | 页面路径大小写：本地不敏感，真机敏感 |

## 这一类要特别小心的事

平台限制会**过期**。基础库在升级，客户端的旧版本在退场，今天不支持的明天可能支持，反之亦然。

所以这一类条目必须写清楚：

- 结论基于什么版本（基础库 / 客户端 / 开发工具）
- 什么条件下这个结论会失效
- 去哪儿核对最新状态

**不写版本的平台限制结论，比不写还危险**——它会让 AI 自信地做出一个已经过时的判断。
