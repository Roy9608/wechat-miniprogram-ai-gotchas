## 写法约定

- 一条只讲一个坑。两个坑有关联就互相链接，不合并
- 代码示例必须能直接跑，不留 `...`
- 涉及版本要求的（基础库版本、客户端版本），标「以官方文档为准」，不写死未经核实的版本号
- **不出现任何具体项目、客户、品牌、业务数据**。示例一律用抽象的「列表页」「卡片」这类说法
- 配套脚本放 `tools/`，条目里**只链接、不重复贴整段代码**——两处各存一份必然会不同步
- 发布前必做：全文扫一遍业务词、项目名、路径、日期、AppID，并确认所有相对链接都指向真实存在的文件

## 一条新条目怎么加

1. 先在 `gotchas/README.md` 这张表里占个 `☐`
2. 写完改成 `✅` 并补链接
3. 如果是新的失败模式（不属于现有四类），先讨论要不要开新分类，别急着建目录
